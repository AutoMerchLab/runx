# Runx CLI 0.8.1

Runx 0.8.1 is a focused operator-runtime hardening release. It makes the
existing GitHub skill path executable through Runx Connect, preserves admitted
capability scopes across the hosted boundary, and closes the remaining gaps
between prepared graph context and effect execution.

## Highlights

- Governed GitHub issue, pull-request, and thread reads and writes now execute
  through the native provider lane with approval, idempotency, and readback.
- Provider capability scopes survive runtime admission and are checked again
  by Cloud without being confused with external OAuth scopes.
- Provider mutation replay now follows the immutable external account rather
  than a replaceable grant or mutable account handle.
- Every official runner now prepares through the complete CLI runtime in one
  admission sweep.

## Added

- Typed single-resource GitHub mutations for issue and pull-request updates,
  thread comments, and comment updates.
- Independent GitHub mutation digest verification and post-mutation resource
  readback.
- Harness coverage for oversized, null, and incorrectly typed payloads plus
  refused non-atomic mutation batches.

## Changed

- Updated `runx.github_sync.v1` in place to carry the exact bounded mutation
  that GitHub will execute.
- Kept provider idempotency runtime-owned and bound exact retries to the
  approved request, external account, and provider result.
- Made managed skill exports remain scoped to the requested skills while
  preserving the package closure needed by harness execution.
- Preserved declared output contracts, artifacts, and operator context while
  binding graph execution before any effect is admitted.
- Made the core-skill audit resolve the OSS workspace consistently when invoked
  through `pnpm --dir`.

## Fixed

- Bound graph execution before effect admission so provider work cannot run
  against incomplete graph context.
- Removed the mismatch where Cloud treated a provider operation name as though
  it were the Runx grant scope.
- Preserved conflicting legacy mutation evidence as deterministic conflict
  state instead of aborting deployment or choosing an arbitrary result.
- Reconciled legacy GitHub and Google account identities through both normal
  Connect reuse and direct provider retries without redispatching exact sealed
  operations.
- Preserved schema-0025 grant-bound replay digests through account-identity
  upgrades and canonicalized them only after an exact match.
- Added a forward-only repair for databases that already applied the original
  account-identity migration; irrecoverably ambiguous rows now fail closed.
- Reconciled provider identities without letting one unknown attempt freeze an
  account: old identities resolve through durable aliases, in-flight attempts
  remain blocked from redispatch, and unrelated exact work can continue.
- Replaced stale same-reference OAuth bindings whenever the inspected account
  identity or effective scope set changes.
- Kept SQL `NULL` outcomes distinct from JSON results when migration or runtime
  reconciliation collapses duplicate mutation evidence.
- Rejected null issue fields, non-string pull-request bases, and NUL-bearing
  thread, label, or assignee fields before digest, approval, provider
  invocation, or idempotency claim.
- Preserved structured operator context and artifact declarations in CLI
  preparation and export fixtures.

## Removed

- Digest-only GitHub mutation plans that could describe a change but could
  never execute it.
- The narrow two-skill admission check superseded by the complete official
  runner sweep.

## Security

- GitHub execution now requires agreement among the runtime-admitted
  capabilities, operation descriptor, grant, exact repository target, access
  class, provider authorization, bounded payload, and readback.
- Unknown provider capabilities remain pass-through vocabulary; supported
  operations cannot silently widen or rename their declared authority.
- Live provider writes fail closed unless exact approved bytes, immutable
  account identity, idempotency claim, provider result, and independent
  readback all agree.

## Breaking changes

- None. This release updates the existing v1 provider and GitHub contracts in
  place and does not introduce a parallel contract family.

## Upgrade guidance

- Upgrade with `npm install --global @runxhq/cli@0.8.1` or your existing Runx
  package-manager channel.
- Reconnect an old GitHub grant if its OAuth authorization predates repository
  access; Runx now refuses grants whose stored capability claim exceeds the
  provider token.
- Run `runx --version` and confirm `0.8.1`.
